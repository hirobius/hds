Each release records its consumer-facing changes in a ledger; one command applies them to your code.

## Run the upgrade

```bash
npx @hirobius/design-system@latest upgrade
```

From your project root, it:

1. Reads the installed version (lockfile, `node_modules`, `--from`, or lockfile history).
2. Applies each later release, oldest first: codemods, the dependency bump, and any dropped dependency your code still imports.
3. Installs and runs your typecheck.
4. Prints four lists: **Fixed for you**, **Looks different** (only what your code uses), **Coming next** (deprecations and the release that removes them) and **Do by hand**.

It refuses, changing nothing, when:

- the installed version is older than <UpgradeFloor />, the oldest release it can upgrade from (follow [MIGRATIONS.md](https://github.com/hirobius/hds/blob/main/MIGRATIONS.md) by hand up to it);
- the run would be a downgrade;
- the target version has no ledger record.

Flags: `--to <version>` (default: the `npx` version), `--from <version>`, `--dry-run` / `--check` (preview on a copy), `--json`.

Exit codes: `0` done with nothing left by hand, `1` work left, `2` refused or error.

## What the ledger holds

Each release has a record in [`upgrade/releases/`](https://github.com/hirobius/hds/blob/main/upgrade/releases), shipped in the package. Each change has:

- **kind** (removed, moved, renamed, deprecated, value-changed, look, behavior…);
- **impact** on an app that does nothing (none, additive, look, behavior, breaking);
- a **plain** sentence, an optional **codemod**, and how to **detect** a use.

A package change can't merge without its ledger entry. Format: [upgrade/README.md](https://github.com/hirobius/hds/blob/main/upgrade/README.md).
