Upgrade command (hds#452): `npx @hirobius/design-system@latest upgrade` ships as the `design-system` bin (and `hds-upgrade`), codemods/upgrade.mjs, Node builtins only. It reads the steps from the copy it runs (upgrade/index.json and upgrade/releases/), finds every importer that declares HDS (the root, pnpm-workspace.yaml, package.json `workspaces`), reads each one's installed version from the lockfile (codemods/lib/installed-version.mjs), then `node_modules`, then `--from`, and recovers an older version from the lockfile at git HEAD or the merge-base with the default branch (a hand bump), and from the lockfile's history when it already says the target; `--from` beats history, and a history version below the floor checks from the floor with a note. Run from inside a workspace package, it refuses and names the workspace root. It refuses with exit 2 and changes nothing below the floor (the exact MIGRATIONS.md message), on a downgrade or for a target with no ledger. It applies the ledgers after the installed version, oldest first: runs their codemods in-process through codemods/registry.mjs (each codemod now takes `skip`, so a workspace root never rewrites a nested package), bumps the range keeping its operator, re-adds a dropped dependency the code still imports, installs and runs the typecheck script or `tsc --noEmit`. It prints Fixed for you, Looks different (only steps whose detect matches the code, codemods/lib/scan.mjs), Coming next (deprecations not yet removed at the target) and Do by hand (steps whose detect matches and whose done does not; a behavior change with nothing to edit is listed to check and does not block), plus a "two copies of HDS" item and a workspace split line; exit 0 done, 1 work left. `--json` validates against the new `$defs.upgradeReport` in upgrade/schema.json. Any earlier removal or manual step the code still matches is listed too, `--dry-run`/`--check` run the codemods on a tmp copy so they list exactly what the run will, and a lockfile still short of the target is a blocking "run `<pm> install`" item, so it never says done before an install. UPGRADING.md and the status release object lead with the one command once the newest release reaches 0.22.0 (`leadsWithCommand` in scripts/upgrade/compile.mjs), so main keeps the manual route until then; the new files ship and check-pack-contents requires them; smoke:consumer runs the packed bin with `--dry-run`. Fixture tests (pnpm, npm, yarn v1/berry, bun, workspaces, git history, floor, idempotence, preview parity, the install with fake managers on PATH).
