Upgrade command (hds#452): `npx @hirobius/design-system@latest upgrade` ships as the `design-system` bin (and `hds-upgrade`), codemods/upgrade.mjs, Node builtins only. It reads the steps from the copy it runs (upgrade/index.json and upgrade/releases/), finds every importer that declares HDS (the root, pnpm-workspace.yaml, package.json `workspaces`), reads each one's installed version from the lockfile (codemods/lib/installed-version.mjs), then `node_modules`, then `--from`, and when the lockfile already says the target recovers the old version from the lockfile at git HEAD, then at the merge-base with the default branch. It refuses with exit 2 and changes nothing below the floor (the exact MIGRATIONS.md message), on a downgrade or for a target with no ledger. It applies the ledgers after the installed version, oldest first: runs their codemods in-process through codemods/registry.mjs (each codemod now takes `skip`, so a workspace root never rewrites a nested package), bumps the range keeping its operator, re-adds a dropped dependency the code still imports, installs and runs the typecheck script or `tsc --noEmit`. It prints Fixed for you, Looks different (only steps whose detect matches the code, codemods/lib/scan.mjs), Coming next (deprecations not yet removed at the target) and Do by hand (steps whose detect matches and whose done does not; a behavior change with nothing to edit is listed to check and does not block), plus a "two copies of HDS" item and a workspace split line; exit 0 done, 1 work left. `--json` validates against the new `$defs.upgradeReport` in upgrade/schema.json.
