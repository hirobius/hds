Every spacing and radius value now has a semantic token, so no design needs a typed px value or a primitive step. New `semantic.space.fixed.*` steps fill the gaps between the comfortable scale rungs and do not move with density: `2xs` 4px, `xs` 12px, `sm` 16px, `md` 24px, `lg` 32px, `xl` 48px (sm–xl equal the compact scale rungs of the same name). New `semantic.radius.scale.*`: `sm` 8px, `md` 12px, `lg` 16px, `xl` 24px, `pill` (fully round), on two new primitives `primitive.radius.16` and `primitive.radius.24`. Each ships as a CSS var (`--semantic-space-fixed-sm`, `--semantic-radius-scale-md`), in `hds.semantic.*`, as Tailwind keys (`p-fixed-sm`, `rounded-scale-md`), as Figma variables, and as Box `sx` values (`p: 'fixed-sm'`, `borderRadius: 'pill'`).

Deprecated tokens now stop tempting agents. The build tags each `$deprecated` token: a `/* @deprecated … */` comment in the CSS, `@deprecated … @removeIn` JSDoc in `hds.*`, `tokenRefs` and the `CSSProperties` var types (editors strike them through), a comment in the Tailwind preset, and they stay hidden from Figma publishing. They are left out of `llms.txt`, `llms-full.txt`, `public/llms/*` and the consumer skill. New `hds/no-deprecated-token` in `hds/recommended` fails a deprecated token as a CSS var, an `hds.*` member or a Tailwind key, and names its replacement. `npx @hirobius/design-system upgrade` runs the new `hds-deprecated-tokens` codemod, which rewrites each one that names a single replacement. From a 2026-10-17 zero-use audit of `src/`, `semantic.space.section.heroMax`, `semantic.space.sidebar.railWidth`, `semantic.docs.space.paragraph` and `semantic.docs.space.inline` are deprecated. **Removal date:** these, along with the hds#206 `layout.*` / `component.gap` / `component.padding` aliases, are removed in 1.0.0. `primitive.space.px6` / `px10` are still removed in 0.28.0, and now point at `semantic.space.scale.xs` / `semantic.space.fixed.xs`.
