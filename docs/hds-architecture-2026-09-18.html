Fewer components, more knobs.

A target architecture for HDS: what ships at the package root, what moves behind a subpath, what stops being public at all — and the five values that carry the variation instead.

Why

The library grew by adding files where it should have turned knobs

ops is the only real downstream consumer: 38 files, and four components — Stack, Badge, Button, Page — account for 41 of its 64 import sites. That is not an argument that the other 93 are waste. It is an argument that there is evidence for 20 and none for the rest.

The structural tell is duplication by category: 22 components are a card, tile, panel or list-item shape, and 21 are a layout primitive. A third of the library covers two ideas. Every time a new need appeared it became a new file rather than a prop on an existing one.

The same habit produced the visual inconsistency: four different radius values for one concept, a type ramp that four components ignore entirely. Bloat and incoherence here are the same defect.

The proposal

Three tiers, one public root

Core (42) — the package root. Brand-neutral, composable, the surface a Figma Community file and a client project both consume. This is the tier that has to be excellent.

Patterns (22) — moved to @hirobius/design-system/patterns. Composed and opinionated: app shells, nav chrome, command palettes, the error and empty states that assume a product. Still shipped, still supported, no longer competing for attention with primitives.

Internal (8) — unexported. Docs tooling, the JSX compiler's vocabulary, creative demos. These never belonged in a consumer's autocomplete.

Folded (41) — absorbed into another component as a prop, variant or slot. This is where the count actually falls, and where the system gets easier to learn rather than merely smaller.

Nothing here deletes behaviour. A fold is an API change with a codemod; a pattern move is an import-path change. The only true removals are the internal tier, and none of those are imported by ops.

The knobs

Five values carry the variation

You already built this. tenants/brutalist-demo/tokens.json re-skins the whole system in two token overrides. The mechanism works; the defaults were distinctive and the component layer bypassed it.

shipped — this commit

1 · Shape — role.radius

One value. rounded-md now resolves to it exactly, so the utility and --semantic-radius-action can no longer disagree; containers step +4px, inset chrome −2px. Default moved 12px → 8px. Verified: brutalist-demo sets it to 0 and every control renders square.

next

2 · Accent — role.accent

#1E2EFD is currently the base, so every consumer starts inside your brand and has to override outward. Invert it: neutral near-black default, and the blue becomes a hirobius tenant overlay like any client's.

next

3 · Edge — border.subtle / border.interactive

One token does two jobs today at #E5E5E5 — 1.26:1, below the 3:1 floor WCAG 1.4.11 sets for a control boundary. Split it: keep the light hairline for decorative edges, add a compliant step (#949494, 3.03:1) for anything that bounds an interactive control.

exists, undocumented

4 · Density — data-density

Comfortable and compact already resolve through --hds-space-*. It is not in the README, so nobody knows it is there.

partial

5 · Type — family + base size

Eleven hardcoded sizes with an inversion at the top (5xl 80px is larger than 7xl 72px), and four components rendering off-scale because they set no size and inherit the browser's 16px. Needs a base size and a ratio, not eleven literals.

Disposition

Every component, with its target

core package root · pattern subpath export · fold absorbed as a prop/variant/slot · internal unexported. ops marks a component the consumer imports today — those need a codemod or a re-export, never a silent break.

Order

Slices, each independently shippable

  1. Shape knobDone. Four radius values → one, verified per tenant.
  2. Neutral the accent, split the borderKnobs 2 and 3. Two token changes plus a hirobius tenant overlay. No component edits.
  3. Fix what does not renderRadio paints nothing (inline spans, 0px wide); segmented items are white-on-white at 1.00:1; toggle is a 16×16 transparent box. Audit A3–A5.
  4. Type rampKnob 5: base + ratio, fix the 5xl/7xl inversion, apply the ramp to the four components inheriting 16px.
  5. Internal tierUnexport the 8 internal components. Zero consumer risk — none are imported by ops.
  6. Patterns subpathMove 22 behind /patterns with root re-exports kept for one minor, deprecation-warned.
  7. FoldsThe 41 API absorptions, one component family per PR, each with a codemod. This is the breaking work and belongs in 1.0.
  8. Gate itA rendered-geometry check so radius, type scale and control height cannot drift again — the existing gates are textual and caught none of this.

Slices 1–5 are non-breaking and can ship as 0.14.x. Slice 6 is a deprecation cycle. Slice 7 is 1.0 and needs the ops codemod ready first.
