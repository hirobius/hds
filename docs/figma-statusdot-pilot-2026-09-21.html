The finding that mattered

Verifying that the fills were genuinely variable-bound rather than baked meant flipping the set to Dark mode. The dots did not change. That turned out not to be a StatusDot bug — every mode-aware variable in the file is identical in Light and Dark.

Hirobius/Component 79 79 0

Code ships a full [data-theme="dark"] block — content.secondary goes neutral-600 → neutral-400, feedback.success goes green-700 → green-400. Figma has none of it. Dark mode on the canvas is a mode that exists and does nothing.

Filed as #252. It is not #245 (that is a code-side CSS-emission bug); both point at dark mode being the least-verified surface in the system. Nothing caught it because check:figma-drift has never run against real state — no snapshot has ever been committed (#236).

Worth being precise about the blast radius: no component rework is implied. StatusDot binds to the right variables. The moment the collections are repaired, it — and all 88 components already in Figma — start rendering dark mode correctly. The fix lives entirely in the variable collections.

Three mechanics worth not rediscovering

  1. A component set does not grow to fit its variants. Resize the set before repositioning children, or the outer column and row are silently clipped — the structure reads correct in metadata while the render is wrong.
  2. defaultVariant is positional, not child order. Figma takes the top-left-most variant. insertChild(0, …) does nothing; moving x/y does. Confirmed by probe.
  3. fills[0].color returns the baked colour, not the mode-resolved one — so it cannot prove a binding is live. Resolve valuesByMode through its alias chain instead. Reading the baked value is what nearly let the dark-mode defect pass as "same colour in both themes, fine".

Open decision

Figma's positional default means "grid reads ascending" and "default variant matches the code default" cannot both hold. Button already drifts on two axes (code secondary/md vs Figma Primary/sm). StatusDot was left ascending and consistent with the library rather than fixed alone — a small consistent wrongness beats an inconsistent rightness across 41 components. Ruling needed before the other 40: #253, defaulting to "keep ascending" on 2026-10-05.

Verdict

The other 40 are mechanical. The recipe is written down in figma/COMPONENT-DRAWING-RECIPE.md. The real cost is not drawing — it is resolving each component's tokens against code first, which is exactly the step that turned up #252.
