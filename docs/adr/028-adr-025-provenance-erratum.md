# ADR-028: Erratum — ADR-025's Figma Provenance Claim Was Wrong

**Status:** Accepted (2026-09-24). Supersedes ADR-025 §Context item 6 (the provenance
claim only) via this Status line; nothing else in ADR-025 changes.

## Context

ADR-025 §Context, item 6, says:

> The Figma side is a partial working file ("HDS Tokens & Components"), edited by hand
> through the MCP server (hds#109). No repo file links to it.

That is wrong. The variables in the published Figma library were **generated by our own
tooling**: `figma-agent-plugin/sync-tokens.js`, a plugin plus a signed WebSocket protocol
envelope plus the `sync-figma-variables.yml` workflow, all built in this repo and cut in
the ADR-018 repo sterilization. The code is preserved, not deleted — it lives on the
`archive/figma-bridge` branch (confirmed present at
`figma-agent-plugin/sync-tokens.js` on that branch), per ADR-018 §2.

Per ADR-009, an Accepted ADR is immutable — a correction is a new ADR that supersedes the
old via its Status line, not an edit to ADR-025's body. This is that ADR. It corrects
provenance only; every other finding and decision in ADR-025 (the Pro-plan capability
table, the one-way sync direction, the local-push-then-snapshot flow) is unaffected and
remains in force.

## Why it matters

It changes what the first `pnpm figma:push` actually is. Under ADR-025's original framing,
the push overwrites **hand-work** — the risky reading, because hand edits can encode
judgment a script cannot see. Under the corrected framing, it is **one generation of our
own sync tooling (`pnpm figma:push` / `figma:model`) reconciling against an older
generation of our own sync tooling (`figma-agent-plugin/sync-tokens.js`)** — the same
source, `hirobius.tokens.json`, run through two different projectors, roughly a year
apart. That is a materially lower-risk operation: there is no design judgment sitting only
in the Figma file that the push would clobber, only an older code path's output.

This also resolves why `check-figma-drift` reported NO-DATA before hds#236's snapshot
landed: there was never a hand-authored source of truth in Figma to diff against — the
missing snapshot was of a previous **generated** state, not of hand-authored design work.

## Decision

ADR-025 §Context item 6 is corrected to read, in substance:

> The Figma side is a working file ("HDS Tokens & Components") whose variables were
> generated by `figma-agent-plugin/sync-tokens.js` (archived on `archive/figma-bridge`,
> ADR-018 §2) — an earlier generation of this repo's own Figma sync tooling, not a
> hand-authored source. No repo file links to it.

This document is the corrected text of record; ADR-025's body itself is left unedited
per ADR-009's immutability rule, with a pointer added at the top of its Context section
(see the companion edit in this commit).

No other finding in ADR-025 changes. The decision to make the repo the source of truth
and run sync one way (code → Figma) already assumed the Figma side could be a fully
regenerated diff target — this erratum just corrects _how_ that Figma side came to be,
which makes that original decision's risk assessment more accurate, not less valid.

## Consequences

- The first `pnpm figma:push` should be described to Adrian and in any risk sign-off as
  "reconciling our own generated output against an older generation of our own generated
  output," not as "automation overwriting hand-work."
- Any future reference to the Figma library's origin (issue bodies, `status.json`, code
  comments) should cite `figma-agent-plugin/sync-tokens.js` + `archive/figma-bridge`, not
  "hand-edited" or "hand-built."
- Checked at the time this ADR was written: `status.json` and issue hds#236 do not
  currently contain the "hand-built" / "edited by hand" framing this erratum corrects —
  hds#250's other cited instance (issue hds#236's description) was already accurate by
  the time this erratum was written, so no further edit was needed there.
- `docs/adr/` has no index file to update; this ADR is discoverable the same way every
  other ADR is, by number and filename.
