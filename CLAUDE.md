# CLAUDE.md

Rules for agents that work in this repo. One line per rule. Detail is in `docs/agent/` (index: `docs/agent/README.md`).
Agents that build with HDS in another app read `AGENTS.md`.

## Focus

- `docs/ai/NORTH_STAR.md` says what HDS is for, who it serves and its non-goals. Anchor scope decisions there.
- The token layer is portable: export tokens, not components.
- If an ask does not serve the North Star, say "North-star drift: park or proceed?" and do what Adrian decides.

## Hard rules (no exceptions, all agents)

- NEVER read, write, create or delete `.env*` files. A person sets the keys. If a task needs a new key, document it in a comment in the script and stop.
- NEVER git push from a local machine: local commits only. A remote Claude Code session may push to its own `claude/*` branch.
- NEVER push to `main`.
- NEVER run `pnpm check:release` or a deploy command.
- NEVER use `--no-verify`. When a gate fails, fix the cause.

## Autonomy (detail: `docs/agent/autonomy.md`)

This section outranks the process rules below. It does not outrank the hard rules.

- Adrian owns the destination: what to build, for whom, priority, money, and anything public or irreversible.
- The agent owns the driving: architecture, code, tooling, tests, naming, and which process steps a task needs.
- Decide and act. Do not ask permission for "how".
- The ops `jev` skill is retired while GitHub Actions is off (ops#773). The agent decides.
- Push back in one line when a rule makes the output worse. Then follow Adrian's call.
- Protect quality with automated checks, not with more steps for agents to remember.
- Report what you decided and why, so Adrian can reverse it. Do not wait for sign-off on engineering calls.
- Leave the repo healthier than you found it. Give each workaround its issue number.
- Message Adrian only when work is done, blocked or needs his decision. Five lines at most.

## Work protocol (detail: `docs/agent/checks-and-merge.md`)

- Before you write code, decide if the request affects UI, layout, CSS or components.
- If it does, run `pnpm typecheck` and `pnpm test` before your final answer.
- If a test fails, fix it yourself and run again. Do not ask the user.
- Report only when the tests are green.
- For a visual change, attach screenshots. Chromatic is off.

## GitHub Actions, checks and merge (detail: `docs/agent/checks-and-merge.md`)

- Do not wait on GitHub Actions checks for a pull request.
- Do not edit `.github/workflows/`.
- Run the checks locally before a push and paste the results in the PR.
- A merge needs an independent `Reviewed: PASS — <sha>` comment on the head commit.
- Only the Release workflow publishes. Agents never publish by hand. Who merges the Version PR: `docs/RELEASING.md`.

## Guardrails (detail: `docs/agent/guardrails.md`)

- `docs/guardrails/registry.json` registers each check script and where it fires. Field reference: `docs/guardrails/SCHEMA.md`.
- `docs/state-surfaces.json` lists each file that describes project state. Index: `docs/ai/DOCS-INDEX.md`.
- Edit the source of a generated file, never the file.
- After you re-read an editorial file, update its `reviewedAt`.
- The pre-push gate `scripts/check-record-freshness.mjs` fails on a stale `status.json` or a missing changeset.
- Each changeset has an upgrade note. Make it with `pnpm upgrade:note`.
- `pnpm check:repo-docs` caps the length of this file, `AGENTS.md`, `README.md` and `CONTRIBUTING.md`.

## HDS work (detail: `docs/agent/hds-work.md`)

- Read `docs/ai/FRONT-DOOR.md` first, then `public/llms.txt`, `public/hds-manifest.json`, then the source.
- For visual work, read `DESIGN.md` first. `DESIGN-HANDOFF.md` is the verbose mirror.
- Look for a local `CLAUDE.md` in a subdirectory before you edit there. Its rules override.
- Use the structured sources, not prose summaries: `public/hds-manifest.json`, `src/app/data/component-api.json` (generated by `pnpm manifest:generate`, not committed), `hirobius.tokens.json`.
- For a new component: create the `.tsx` with existing tokens, run `pnpm manifest:generate`, verify the docs page. Never ask the user to update the manifest.
- Do not use repeated outlined cards as the default layout of status or overview UI.
- Do not append badges to prose. Put status in one consistent slot.
- Do not guess an architecture decision. Read the routing document first.
- Token and manifest rules: `docs/rules/MANIFEST_SYNC.md`.
- React component rules: `docs/rules/REACT_COMPONENTS.md`.

## Figma (detail: `docs/agent/figma-sync.md`)

- Code is the source of truth. Sync runs one way, from code to Figma. Architecture: `docs/adr/025-figma-sync-pro-architecture.md`.
- In the HDS library, agents may change components but never delete and never publish. Adrian publishes.
- Draft a new component in HDS Staging, then redraw it in the library and delete the draft.
- Tokens reach the library only from code. Never run a `--prune` build.
- A client's brand never enters the shared library.
- Batch MCP calls. Never retry a rate-limit error.
- Runbook: `figma/README.md`.

## Sub-agents (detail: `docs/agent/sub-agents.md`)

- Pick the cheapest model that can do the job. Give the reason in one line in the dispatch description.
- Default to minimum effort.
- Use `isolation: "worktree"` when two agents can touch the same file.
- A coordinator session never runs the Agent tool in its own thread. It delegates to worker sessions. See `docs/agent/sub-agents.md`.

## Lint (detail: `docs/agent/lint-fix.md`)

- NEVER run a full-codebase `pnpm lint:fix`. Fix one rule at a time, then run `pnpm typecheck && pnpm exec vite build`.
- If the auto-fix of one rule touches more than 50 files, stop and ask Adrian.
- Never auto-fix `react-hooks/exhaustive-deps`.

## Skills (detail: `docs/agent/skills.md`)

The engineering skills in `.claude/skills/` are mandatory routing, not suggestions. `skills-lock.json` pins the vendored ones.

- Build anything: `/implement` and `/tdd`.
- Epic or spec: `/to-spec`, `/to-tickets`, `/implement-spec`. Run `/grill-me` first if the plan is unclear.
- Before any PR: `/code-review`, then write the body with `/pr`. `scripts/hooks/check-pr-body.mjs` enforces the body.
- End of a real session: `/retro`.
- A bug: `/diagnosing-bugs`, then `/tdd`.
- A new module or design-touching work: `/codebase-design`. Design-debt sweep: `/improve-codebase-architecture`.
- Issue lifecycle: `/triage`. A lane with many decisions: `/wayfinder`.
- A perf-budget failure: `performance-optimization`. Never raise a budget to get green.
- Design-touching UI: `/design-review`. A visual bug: `/visual-fix`. UI polish: `/impeccable`.
- Docs copy: `humanizer`. UI second pass: `web-design-guidelines`.
- Where an Osmani skill overlaps a Pocock skill, run the Pocock skill.

## Issues and tracker

- The tracker is GitHub Issues in this repo. Never use a local TODO file.
- Labels: `backlog`, `bug`, `blocked`, `needs-adrian`, plus the Ralph labels in `docs/agent/ralph.md`.
- Use sub-issues for epic to child. Write "Depends on #N" in the body for a prerequisite.
- Tracker operations: `docs/agents/issue-tracker.md`. Triage labels: `docs/agents/triage-labels.md`. Domain docs: `docs/agents/domain.md`.

## Fleet hub (detail: `docs/agent/fleet.md`)

- This repo is part of the Hirobius fleet. The hub is the `hirobius/ops` repo.
- State is derived. Set `focus` in `status.json` only when the direction of this repo changes.
- Read the ops HANDOFF before a cross-project decision.

## PR previews (detail: `docs/agent/pr-previews.md`)

- Vercel preview builds are off. Never turn them on and never add `[preview]`.
- Each visual PR carries screenshots: 390x844, light and dark, six at most, inline.
- For a PR with no visual change, write "no visual change".
